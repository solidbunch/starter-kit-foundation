# config/ — runtime configuration

Everything here is mounted read-only (or generated) into containers by `docker-compose.yml` /
`docker-compose.toolkit.yml`. Nothing under `config/` is application code — it's infra
configuration, templated per environment.

```
config/
  environment/   .env.main, .env.type.{local,dev,stage,prod}[.override], .env.secret — see root CLAUDE.md
  php/           php.ini + per-env overrides (dev.d/, local.d/, prod.d/, stage.d/) + local-only xdebug.ini
  nginx/         *.conf.template — rendered to *.conf at container start via envsubst (official nginx image behavior)
  cron/          crontabs/root — the cron container's crontab, no restart needed after edits
  certbot/       cli.ini — default flags for every certbot invocation in the certbot toolkit container
  ssl/           live/<domain>/{fullchain.pem,privkey.pem} — gitignored except readme.md/.gitkeep
```

## Email (`config/environment/.env.main` SMTP block)

No internal mail routing (deliberately avoided — domain/IP reputation, resource cost, security).
`SMTP_HOST`/`SMTP_PORT`/`SMTP_SECURE`(`none`|`ssl`|`tls`)/`SMTP_FROM`/`SMTP_NAME`/`SMTP_DEBUG` live
in `.env.main` (default: Gmail SMTP, `tls`, port 587) with per-env overrides; `SMTP_USER`/`SMTP_PASS`
are secrets (`.env.secret`/`sh/env/.env.secret.template`). `local` overrides point at the
`mailhog` container (`SMTP_HOST=mailhog`, port `1025`, `SMTP_SECURE=none`) — run `make mailhog`
and view caught mail at `<domain>:8025`. Any real SMTP provider works (Gmail, SES, Mailgun, etc.).

## PHP config (`config/php/`)

`php.ini` is the shared base. Per-environment `.d/` folders (`local.d/`, `dev.d/`, `stage.d/`,
`prod.d/`) only apply in that `WP_ENVIRONMENT_TYPE` — e.g. `local.d/xdebug.ini` is what makes
Xdebug local-only (see `debug.md`). Add environment-specific PHP settings to the matching `.d/`
folder, never by branching on environment inside `php.ini` itself.

## Nginx config (`config/nginx/`)

Files are `.conf.template`, not `.conf` — the official nginx image's entrypoint renders every
`/etc/nginx/templates/*.template` to `/etc/nginx/conf.d/*.conf` via `envsubst` on container start,
substituting vars like `${APP_DOMAIN}`, `${APP_PROTOCOL}`, `${APP_BA}` from the container's
environment (nginx always listens on 80/443, hardcoded in the templates). **Never edit a rendered
`.conf` file directly** — it
is overwritten on every container start; edit the `.conf.template` and restart/recreate.

- `default.conf.template` — entrypoint that includes `config/{http,https}.conf.template` based on
  `${APP_PROTOCOL}`.
- `config/http.conf.template` / `https.conf.template` — protocol-specific server blocks
  (http→https redirect, www→non-www redirect, ACME challenge passthrough for certbot).
- `config/common.conf.template` — the shared WordPress serving rules: PHP routing, static asset
  caching, REST API/sitemap/robots passthrough, deny rules for `wp-content`/`wp-includes` direct
  access and PHP execution inside `uploads`. Changes to caching headers, deny rules, or upload
  size limits (`client_max_body_size`) go here, not in the protocol-specific templates.
- `config/partials/` — small includes: `headers.conf`, `gzip.conf`, `logs.conf`, `php.conf`
  (fastcgi pass), `ssl.conf`, and `ba_enable.conf`/`ba_disable.conf` (Basic Auth toggle, selected
  by `${APP_BA}` / `${APP_BA_WP_LOGIN}` — the actual htpasswd file is generated by the nginx
  image's `15-setup-basic-auth.sh` entrypoint script, not stored here).

## Cron (`config/cron/crontabs/root`)

Runs inside the dedicated `cron` container (not WP's HTTP-triggered cron — see root `CLAUDE.md`
"Intentional Quirks"). Current jobs: WP cron every 5 min (`docker compose exec php ... wp-cron.php`
under a `flock` lock), daily/weekly DB+media backup (`sh/cron/start-backup.sh`), Certbot renewal
+ nginx restart at 03:30, and Let's Encrypt log rotation. Edits apply on save — no container
restart needed. Keep new jobs `flock`-guarded if they must not overlap runs.

### Automatic backups

Gated by `APP_WP_BACKUP_ENABLE` (`1`/`0`) in each `config/environment/.env.type.*` — on by
default in all four environments. `sh/cron/start-backup.sh {daily|weekly}` (invoked by the two
backup cron lines above) exports a DB dump (`sh/database/export.sh`) + uncompressed media archive
(`sh/media/export.sh -n`) into `./backups/{daily,weekly}/`, combines them into one `.tar.gz`, and
prunes old ones — daily backups older than 6 days, weekly older than 30 days
(`find ... -mtime +$MODE_TIMER -delete`). `./backups/` is gitignored; nothing here restores
automatically — use `make import`/`sh/database/import.sh` + manually extract the media archive
to restore from one.

## Certbot (`config/certbot/cli.ini`)

Default flags (`agree-tos`, `non-interactive`, `authenticator = webroot`, `webroot-path`) applied
to every certbot invocation — see `docker.md` for the full SSL bootstrap flow driven by
`sh/system/certbot.sh` / `make ssl`.

## SSL (`config/ssl/`)

Gitignored except `readme.md` and `.gitkeep`. Populate `live/<domain>/` manually per
`config/ssl/readme.md`, or let `make ssl` generate it. Never commit real certs/keys here.
